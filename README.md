# Customer Churn ML Platform

A reproducible tabular machine-learning project that takes a small synthetic customer dataset through validation, preprocessing, training, evaluation, and an API prediction endpoint.

## Why this project

This project connects data preparation, model training and prediction in one small application. The sample data is synthetic.

## Quick start

Python 3.11+ is required.

```bash
python -m venv .venv
# activate the environment, then:
pip install -r requirements.txt
python -m churn_ml.train --data data/customers.csv --model artifacts/churn.joblib
uvicorn churn_ml.api:app --app-dir src --reload
```

If you need a fresh deterministic sample dataset, run `python scripts/make_dataset.py --out data/customers.csv`.

The API exposes `GET /health` and `POST /predict`. Example payload:

```json
{"tenure_months": 4, "monthly_charges": 72.5, "support_tickets_90d": 3, "contract": "month_to_month", "payment_method": "electronic"}
```

The training command prints ROC-AUC, precision, recall, and a confusion matrix on a stratified holdout split. These are measurements on generated data only; they are not evidence of real-world performance.

## Engineering details

- Schema checks reject missing columns, invalid categories, and non-finite numeric values.
- A scikit-learn `Pipeline` keeps scaling, one-hot encoding, and logistic regression together to reduce train/inference skew.
- A seeded stratified split makes experiments reproducible.
- The API returns a churn probability and applies a configurable default threshold of `0.5`.
- Model files are created locally and excluded from Git.

## Tests

```bash
python -m unittest discover -s tests -v
```

## Limitations

The synthetic data is intentionally small and generated by a transparent rule. It is suitable for demonstrating pipeline mechanics, not selecting customers for real interventions. A real deployment needs validated, consented data, calibration and fairness checks, monitoring, and a retraining policy.
